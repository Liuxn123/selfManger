# selfManger v1.0.1 使用说明

# 当前源码调整（2026-10-28）

Hermes、通用 Agent 管理与备份、会话读取及应用内 Codex 任务执行已移除。项目 Agent 管理文档和项目 Skills 保留；已有登记、资料及旧备份不会自动删除。下文涉及已移除功能的历史说明不再适用。


## 1. 先看这里

当前源码补充：项目「任务」页可编辑名称、日期和备注，可单独编辑状态或确认删除，已完成任务排在后面。AI 手动完成状态与历史完成记录分别保存，不会凭手动勾选生成执行证据。编辑保存失败时弹窗保留草稿，可修改后重试。

项目任务统一保存在 SQLite。历史 TASKS-AI/TASKS-MANUAL 文档可通过“迁入旧任务（一次）”预览并迁入；冲突时保留数据库记录，原文件不修改或删除。迁入后不再读取这些文件的后续改动。旧个人资料只导入一次，保留行动时间、计划日期/进度/关系、复盘范围/正文、重复规则和打卡记录；原件留在原处。个人行动在计划中编辑，并与项目共享同一 SQLite 记录。

selfManger 是管理个人行动、项目和知识资料的工作台。先看今天做什么，再进入计划、项目或知识库；需要备份时进入数据安全。

侧栏顺序为今日工作台、计划与待办、项目管理、工具与环境、知识库、数据安全和设置。底部两行显示日期与提醒、使用说明与运行模式；悬停日期查看完整年月日。内容区不再保留空顶栏。通用 Agent 管理/备份/恢复入口已移除；项目 Agent 文档和 Skills 保留，旧登记与资料不会自动删除。


建议先在“项目”选择自己的规范工作区，再在“工作台”写今天的计划。没有工作区也能先写每日计划；知识库资料需要选择 Vault。

## 2. 工作台

工作台默认显示今天，与“计划与待办”读取同一批个人行动：包括当天事项、当天的重复事项和此前未完成的行动；此前事项保留原日期。可直接勾选完成，双击到计划与待办中编辑。日期框可以查看过去或未来一天，左右箭头翻日，“回到今天”返回。项目与备份状态仍表示当前状态。

工作台顶部的“记录行动”按钮和今日行动卡片中的“添加行动”按钮使用每日计划正文编辑器，按工作台所选日期写入 SQLite；“查看每日计划”和六类计划入口进入对应分类并保留所选日期。周期事项勾选只记录当日打卡，悬停行动可查看所属计划和项目。提醒显示到期日期及逾期信息；周/月复盘提醒定位对应历史周期并切换周/月模式，已有对应复盘不再提醒。工作空间提供计划、项目、知识库、数据安全和设置入口。

## 计划与待办：个人行动中心

侧栏入口为“快速新建、每日计划、长期计划、周期计划、周月复盘、项目计划”。行动可以独立存在；计划期限和项目关联都可以留空。工作台与计划页读取同一批个人行动。

- **快速新建**：与其他五个入口同级，使用固定模板编辑计划正文。标题、正文、日期、关系、状态和周期规则统一保存在 SQLite，不为新记录生成 Markdown 文件。首次打开时会检查数据库登记的旧计划文档，将与原文哈希不同且格式有效的内容迁入 SQLite；迁移失败会显示需要检查的文档，修复后重启可重试。旧文档始终留在原处；一次性迁移完成后，应用不再读取后续文件修改。
- **每日计划**：添加当天行动，也可以切换日期查看或编辑历史行动。完成状态与工作台同步；标题栏和列表上方都能开始新增。
- **长期计划**：集中查看个人和项目关联计划；计划可不设截止日期。点击“新建长期计划”填写正文后保存，返回列表继续管理。项目计划在此显示同一条 SQLite 记录，编辑后两处同步。
- **周期计划**：只显示重复行动系列，支持按天、按周或按月重复。点击“新建周期计划”设置规则；每天分别记录打卡状态，不会因为完成一次而结束整个系列。
- **周月复盘**：查看所选日期所在周、月的安排与完成情况，周期计划按每次打卡统计。分别新建周/月复盘，保存后返回；切换日期可补写历史复盘，点击历史记录继续编辑。周末和月底在工作台及复盘页提醒，已有对应复盘不再提醒。
- **项目计划**：仅列进行中项目的关联计划，可编辑期限、正文、状态；新建时选择项目。计划同时显示在长期计划中；在编辑器点击“安排到每日计划”，选择执行日期并保存，即生成关联原计划和项目的每日行动，在工作台同步管理。

项目计划页可在搜索框旁选择具体项目，或查看全部进行中项目。除关联计划外，“关联行动 / 手动任务”只显示项目管理共用任务库中的个人行动和手动任务；AI 规划仍在项目管理中查看，不参与此页列表、搜索及完成统计，不需要重新新建或复制。选择和搜索可组合使用，刷新/保存后保留所选项目，新建弹窗默认关联该项目。列表状态默认只读：待完成为橙色、进行中为蓝色、已完成为绿色；点击“编辑状态”，在弹窗选择后点“保存”写入共享 SQLite 记录，取消不写入。周期行动只修改执行日的打卡，不结束系列。保存期间不能重复提交或关闭弹窗；失败保留选择可重试，列表刷新回实际保存值。个人行动可继续编辑正文，手动任务可查看详情。不同工作区的同编号记录不会混入。

快速新建按横向标签选择每日、长期、周期、项目或复盘类型；复盘可继续选择周/月。带行号的 Markdown 正文编辑区上方展示由表单控制的类型与日期，正文可以自由编写，一级标题可作为计划名称。“保存并打开”会写入 SQLite 并进入对应模块。右侧展示记录类型、模板分类和最近记录；旧 Markdown 原件仍存在时可双击打开。

快速新建和分类弹窗共用每日、长期、周期、项目、周复盘、月复盘六份内置正文模板；不预置示例任务。类型、日期、关联和周期规则由表单保存，正文写入相应 SQLite 字段；周期打卡状态由日期记录维护，正文不作为打卡真源。旧计划 Markdown 不再随应用编辑更新。

每日、长期、周期、项目页的“新建计划”及周/月复盘按钮均打开当前分类的独立弹窗，使用对应正文模板；保存后留在原页，日期和筛选条件保留。弹窗取消或保存失败会保护当前编辑内容，快速新建中的草稿保持独立。计划卡片和计划编辑器中的“安排每日行动”同样使用弹窗。

每日和周期页显示完成概览、可勾选事项行与编辑入口；长期和项目页显示期限、项目关联、进度和安排每日行动的计划卡片。周月复盘按“周复盘 / 月复盘”切换完成统计、期间安排、历史总结及关联计划；长列表可展开。已有本期复盘时直接编辑原记录，避免重复创建。

编辑停顿后，草稿会自动保存到本机管家数据，下次打开恢复，包括所选类型、日期及关联。界面只有在写入成功后才显示“草稿已自动保存”；草稿不会生成正式计划，正式 SQLite 记录仍需点击“保存并打开”。

选中行动才打开详情。宽窗口在右侧编辑，窄窗口进入详情后可“取消”返回列表。名称、日期和重复设置直接可见，项目、所属计划、备注、优先级收在“更多选项”。保存成功后关闭，失败保留草稿；未保存切换页面或退出会询问是否放弃，外部记录改变时拒绝覆盖。

重复设置支持每天、每周、每月，可设结束日期。选择“每周”后勾选周一至周日，可多选，至少保留一天；选择“每月”后指定 1–31 号，没有该日期的月份跳过。开始日期决定规则从哪天生效，不限制重复星期或几号。新建弹窗、快速新建、详情编辑共用规则，规则保存在 SQLite 的重复规则和逐日打卡表中。旧每月计划沿用开始日规则，原月末计划继续在每月月末出现，可手动改成固定几号。每一天分别记录完成情况：今天勾选不会完成整个系列，明天仍按规则出现；查看未来安排不会提前生成一批任务。取消重复后成为普通行动，已有逐日完成记录保留。

所有已保存的每日、长期、周期、项目计划及周/月复盘均可删除：在列表点击“删除”，或从编辑界面删除，确认后从各入口移除。删除长期/项目计划时保留已安排的行动并解除关联；删除周期计划会删除整个系列及其打卡记录。SQLite 会保留删除快照；关联的旧个人 Markdown 原件留在原处，不再移动或更新。界面暂未提供恢复按钮。旧项目任务文档也保留原样，不会恢复已删除记录。

关联项目的行动在项目详情中直接显示，与个人列表共用一条数据库记录，完成状态同步。项目的 AI 规划任务与关联行动均由 SQLite 保存，个人收集箱不自动接收 AI 规划任务。

旧计划文档在首次读取时按数据库登记的文件映射检查，内容哈希不同且格式有效的最终修改会迁入 SQLite；原文件保持不变。格式错误或无法读取的文档会提示检查，修复后重启可再次尝试。迁移完成后，外部 Markdown 编辑不会再改变应用记录；备份仍包含个人计划资料目录。此前已迁入的项目文档任务继续保留在 SQLite 中，并与个人行动视图隔离。

工作台统计取自真实行动和项目数据，重复事项计入当天行动完成数，到期计划单独提示；空白状态不使用演示数字。

小窗口减少装饰并保留双栏，页面可滚动，长项目说明省略并可悬停查看全文。

项目卡片展示真实阶段与下一步；双击继续。最近工作表示最近从管家进入的项目。资料保护展示已记录的备份结果，不代表当前 Agent 或服务器已在线。点备份卡片进入对应数据安全登记。

### 旧版每日 Markdown 导入

旧版本用每日 Markdown 保存日程和勾选任务。当前应用首次检查个人资料时可将符合旧格式的行动一次性迁入 SQLite，源文件保留；迁入后，外部编辑不会再改变应用任务，也不会由应用写回每日 Markdown。新建行动请使用工作台的“记录行动”或“添加行动”按钮及计划页表单；编辑和勾选行动使用 SQLite 表单。

```markdown
# 2026-10-05

## 日程
- 09:00 selfManger开发
- 14:00 Hermes 测试

## 今日任务
- [ ] 测试恢复
- [ ] 完成阶段总结
- [ ] [高] 核对恢复结果 @10:00

## 工作记录
今天发现的问题可以记在这里。
```

上述示例只说明旧版导入格式，不是当前应用的保存格式。日程文字不会发送通知或连接日历服务。

项目 STATUS、Agent 协作 TASKS、HANDOFF、项目笔记及知识库文件仍可通过 Obsidian 编辑；项目页面按各自刷新入口加载内容。应用任务保存在 SQLite，与这些协作 Markdown 不做持续同步。

双击需要继续的项目进入项目。最近工作仅表示你从今日进入过的项目，不推测 Agent 对话内容。暂停项目与最近操作失败 / 中断显示在“需要我处理”；双击进入对应页面。工作笔记在“操作记录”页的“我写的笔记”中查看，内容保存在 SQLite 并随数据库备份。

午夜后首页会切换到新一天。应用内新建的行动和计划只写入 SQLite，不会按日期创建 Markdown 任务文件；程序启动也不会批量写入知识库。

## 3. 项目

选择包含 `agent/projects.json` 的工作区根目录；普通项目目录不是规范工作区。也可选择空目录初始化，随后点“新建项目”。编号按既有规范分配且不复用。

新建项目时分别填写项目名称和英文目录名。项目名称用于界面、索引与 Markdown 标题；英文目录名用于 `projects/<编号>-<目录名>` 与 Obsidian 入口，保存时只保留英文/数字并转换为小写连字符格式，避免空格、中文和文件系统保留字符影响路径。点“翻译为英文”会将项目名称发送至 Google 翻译并填入目录名；也可手工编辑。在线翻译不可用时不会阻止创建，只需填写英文目录名。

新建窗口按“项目信息 → 开发规范 → 技能与资料（可选）→ 确认创建”四步完成，仅最后一步显示“创建项目”。默认开发规范为三条，可直接使用，也可编辑或通过“导入规范…”载入 Markdown；内容写入 AGENTS.md。Skills 完整复制到项目，知识资料保留引用；筛选不会取消已勾选项。“导入 JSON 模板 / 另存为模板”用于复用规范和附加文本文件，不包含本机资源选择。已有工作区模板原文保留。

Skills 可显式从已登记本机 Agent 的已有目录发现，或手动选择含 SKILL.md 的目录；知识资源复用已加载索引，也可刷新索引或选择本地文件。全部以勾选为准。Skills 连同脚本、资源和空目录完整复制到项目 `.selfManger/skills/<技能目录名>/`；知识资料继续保留引用，原始技能与资料不改动。初始化将选择及副本位置写入 `.selfManger/config.json`，在 `.selfManger/RESOURCES.md` 中说明，并从 AGENTS 提供各技能 SKILL.md 入口；不执行技能脚本、不修改全局 Agent 原生规则，也不自动向模型发送知识内容。Agent 是否加载某个 Skill 必须依据该 Agent 的实际规则确认，不能仅凭配置中的记录判断。

“确认创建”用项目名称、目标、保存位置、所选规范、要复制的技能和关联资料说明创建结果，不再直接展示配置或 Markdown 源文。最终编号在创建时分配；非法模板、技能同名、失效来源和技能树中的链接会在分配编号前拒绝。项目内技能副本可随项目迁移；知识引用与原始技能来源记录尽量保存为相对路径，跨盘保留绝对路径，迁移后需核对。复制中发现来源变化或目标冲突会停止并保留现场，不覆盖已有文件。模板不能覆盖基础管理文档、Agent 私有配置和隐藏目录，不运行任何模板脚本。本阶段只改新建项目，已有项目不会自动迁移，记忆和开发会话功能尚未加入。

创建成功后打开“项目 AI 提示词”，选择初始化或接手并复制给 AI，附上本轮需求。弹窗提供完整可复制约定；新生成的 `agent/PROMPTS.md` 合并公共规则，仅保留两段用途说明，减少重复。九列任务格式、里程碑、来源分流与执行边界仍保留。旧项目文档和自定义模板不自动覆盖。

已有项目可在“Agent 文档 → AI 提示词”查看并复制“已有项目接手”提示词。AI 应说明当前阶段、本轮目标与验收条件；实质任务收尾时更新 STATUS、Agent 协作清单 TASKS.md 并追加 HANDOFF。应用业务任务由项目“任务”页保存到 SQLite；旧 TASKS-AI/TASKS-MANUAL 仅作历史资料，可一次性迁入。回复需说明完成内容、实际验证、未验证事项和下一步。归档或状态异常项目暂不可从该入口接手。

初始化或制定计划时，AI 应实际编写 `agent/MILESTONES.md`，按“状态 / 里程碑 / 目标日期”表格记录阶段成果和验收条件；新阶段填待开始，未知日期填待定，并保留用户已有内容。Agent 开发协作事项写入 `agent/TASKS.md`；应用业务任务通过 selfManger 项目“任务”页管理，不另建 Markdown 副本。

例如“想学习项目并先运行起来，但本轮先了解、只写文档”：AI 本轮应输出项目概览、运行说明、学习路线与里程碑，并将后续行动列为 AI 规划；不执行安装、启动或业务代码/配置修改，不把运行计划写成已验证。长期目标不能扩大本轮授权。应用内复制提示词读取当前内置约定；已有项目落盘的 `PROMPTS.md` 和自定义模板不会被自动覆盖，需要时按新约定手动合并。

左侧点项目卡片，顶部显示名称、编号和生命周期。宽屏左侧展示介绍，右侧展示当前阶段、负责人、计划周期和优先级；下方补充已有成员、标签、仓库和最近更新时间，缺失关键字段显示“未设置”。编辑入口在标题右侧，常用操作集中底部；窄窗口改为上下排列。介绍由你通过“编辑项目信息”编写并保存到 `agent/projects.json`，与 STATUS 的阶段、进展和下一步分开；留空会显示编辑提示。项目编号、工作区相对路径、Vault 入口和已发编号以 `agent/projects.json` 为准；STATUS 中的项目编号须与登记相符，生命周期只从 STATUS 读取。项目索引是由登记和状态生成的浏览视图；SQLite 任务只保存项目编号和工作区路径作为关联。每个介绍最多 4000 个字符。项目页默认显示进行中项目，可切换到已归档；选择项目时会记录最近使用时间，进行中项目按最近使用顺序排列。旧状态中的非归档项目会在列表中统一显示为“进行中”；归档后重新启用也会回到进行中。工作区路径可通过右侧“⋯”维护菜单切换。归档会更新 STATUS 并从 Obsidian `03-项目`目录中移除登记的项目目录联接，真实项目目录和登记路径保留；重新启用会恢复该联接。永久删除只对已归档项目开放，点击“删除项目”后需准确输入完整项目名称。删除会清除项目目录和仍存在的登记 Obsidian 入口，已发编号仍保留；统一任务、计划与资源记录不会自动删除。执行前请核对项目引用和备份。

“概览”左侧展示里程碑、任务和统一的“项目资料”，右侧整列展示项目动态；窄窗口按宽度分行显示。项目资料合并展示项目文件与知识库关联资料，每项标注来源，点击后按原入口打开；概览最多预览六项，“查看全部”可浏览完整列表并双击打开。“添加资料”菜单提供“上传项目文件”和“添加知识库资料”。两种来源保留原存储位置与关联身份，文档和知识库页面继续提供各自管理入口。

上传项目文件支持一次选择多个文件，副本会逐个复制到当前项目的 `文档/` 目录，原文件不移动、不修改；遇到同名文件会拒绝覆盖。在“文档”标签可预览或打开文件；Markdown 可交给 Obsidian 编辑。Agent 的 STATUS、TASKS、HANDOFF 等协作文件单独放在“Agent 文档”标签。任务卡和“任务”标签读取 SQLite 任务库；任务页可直接创建、编辑、关联和删除任务。历史 TASKS-AI/TASKS-MANUAL 可一次性迁入，原文保持不变，之后应用不再同步。统计读取当前项目任务库、资源关联和 HANDOFF。负责人、成员、起止日期、优先级和仓库地址可从顶部“编辑项目信息”编辑，保存在 projects.json 的可选字段中。

“任务”标签分为 AI 规划任务与关联行动两张卡片。可在应用内创建和编辑任务，也可用“迁入旧任务（一次）”预览迁入历史 TASKS-AI/TASKS-MANUAL 文档；数据库已有记录时保留数据库版本。迁入完成后，列表只读取 SQLite，旧文档后续修改、删除或状态变更不会影响任务。手动调整 AI 任务状态不会生成 Agent 执行完成记录。“Agent 文档”标签收纳 STATUS、HANDOFF 和阶段总结预览。阶段和下一步由你在 STATUS 中维护，日志与阶段总结由你在 HANDOFF 中维护。“资源”标签显示知识库中关联到当前项目的资料；关联在知识库资料信息中维护。旧 STATUS 中的 `resources` 字段保留原文，但不再作为应用关联来源。Agent 标签只显示 STATUS 中明确关联的 Agent 编号。

“近期任务”分开展示 AI 规划与关联行动。“清单任务”统计两类任务的总数。应用任务以 SQLite 为准；Agent 协作清单 `agent/TASKS.md` 不会导入应用任务列表。

日志数来自 HANDOFF 中按日期追加的记录，包含阶段总结；最近更新来自 STATUS 的 updated 字段，不代表 Agent 在线。关联资源数来自知识库 SQLite 元数据中指向当前项目的条目。旧 STATUS 的 `resources` 字段不会驱动项目关联列表，项目资源标签不显示 Agent。

标签入口：概览、任务、文档、笔记、资源、Agent、设置。“笔记”页提供当前项目“笔记”目录入口。首次使用时先在设置中选择包含 `.obsidian` 配置目录的 Obsidian 知识库根目录并保存；之后点“打开项目笔记目录”会通过 Obsidian 打开工作区中的对应笔记目录。目录不存在时会先在项目中创建，仍由你直接编写 Markdown 笔记。若提示知识库与项目入口不匹配，请选择正确的知识库根目录或检查项目登记中的 Obsidian 入口。

STATUS 是项目进度真源，TASKS.md 记录 Agent 协作事项，HANDOFF 按日期追加日志。应用任务统一保存在 SQLite；旧 TASKS-AI/TASKS-MANUAL 可一次性迁入，源文档保留为历史资料。

需要修改 STATUS、TASKS 或 HANDOFF 时，在项目对应标签点击“在 Obsidian 中编辑”维护原文件。应用任务在项目“任务”标签中编辑。项目笔记保存在真实“笔记”目录，Obsidian 与管家共用。进入项目时读取一次；外部修改后点左侧“刷新”查看 Markdown 预览。项目页不按文件变化或窗口切回自动刷新。

项目标题旁的 Git 按钮可查看状态，并在详情中暂存全部变更、提交已暂存文件、快进拉取和推送。尚无仓库时可在项目目录初始化；如项目登记了仓库地址，会添加为 `origin`。暂存全部会先确认；提交需要填写说明；拉取只允许快进，遇到分叉时会停止并提示。项目目录包含多个仓库时可选择目标仓库。HTTPS 远程可在“设置”保存访问令牌，SSH 远程使用本机 SSH 密钥/ssh-agent。标准模式将令牌存入系统凭据库，便携模式存入加密口令库；令牌不写入项目设置、远程 URL 或日志。未设置 Git 提交者姓名/邮箱时，需先按 Git 提示配置。归档会把 STATUS.md 的生命周期改成“archived”，并暂时移除 `03-项目`中的项目目录联接；不会搬动或删除 `projects/`中的项目文件夹。重新启用会在登记的原路径重建联接。“项目总览”和“归档项目索引”按状态分类。旧 `L-` 项目也可直接切换状态和继续维护。归档不等于备份。

## 4. 阶段总结

阶段总结直接由你编写并追加到项目 `agent/HANDOFF.md`，使用“日志”标签和“在 Obsidian 中编辑”打开原文件。

记录时区分已完成和待验证的内容，并保留原有交接记录。

需要借助 Agent 整理时，可自行复制项目状态和任务内容到常用 Agent；管家不会自动发起 AI 调用。

原 HANDOFF、日志和阶段总结共用同一份 Markdown，不额外生成 SUMMARY / PROGRESS / REFLECTION 文件。

资源关联在知识库条目的项目关联字段中维护，关联元数据保存在 SQLite；项目资源标签只展示对应知识库条目，不展示 Agent。STATUS 中原有的 Agent 引用保持不变。

## 5. Agent

项目 Agent 状态和任务清单由项目 Agent 文档维护。通用 Agent 管理、聊天记录读取和 Agent 备份/恢复入口已移除；本地已有资料与旧备份不会自动删除。


## 6. 知识库

知识库采用左侧目录、右侧资料工作区：默认列表，选中后直接阅读；宽窗口列表和阅读区左右并排，窄窗口自动改为上下排列，可拖动分隔线调整。搜索位于资料列表顶部，“添加资料”位于页面右上方。取消整页滚动，各列表与阅读内容各自滚动；空库/空专题与顶部共用“添加资料”弹窗。资料构成图、底部重复收集输入和重复的专题添加按钮已移除。

首次进入读取知识库；后续刷新仍检查目录、文件和资料描述变化，但不重复写入未变化的索引。同一知识库在本次运行中复用正文缓存，文件属性变化后重新读取；缓存受全文读取预算限制，切换知识库或重启后重新读取。缓存不作为资料真源，也不写入新的正文数据库。外部编辑后可从“管理”刷新索引。

顶部统一为“添加资料”，弹窗内切换文件、链接、笔记、整个目录。空状态使用相同入口。浏览专题时默认保存到当前专题；全部资源、收件箱、最近使用、收藏等视图默认保存到收件箱，保存前均可更改位置，支持深层专题。文件默认复制并保留原件，也可选择仅保存原文件引用；整个目录复制到所选位置，保留原目录名、子目录结构和文件，原件不变；同名目录拒绝覆盖，复制失败或取消会清理本次未完成副本。文件引用在原件移动或删除后会失效。拖入文件或单个目录也先进入弹窗确认。链接保存为网址记录，笔记保存为 Markdown；同名文件拒绝覆盖并说明原因。刷新索引、打开当前专题目录及知识库目录集中在独立“管理”菜单。类型、排序和标签位于“筛选”折叠区，卡片视图仍可切换。

“新建笔记”直接打开笔记表单，标题可不填，自动使用正文首行；用途和标签默认收起，保存成功才关闭，失败保留草稿。选中已有笔记后点击“编辑笔记”直接在阅读区编写，可 Ctrl+S 或点“保存笔记”；编辑时进入专注区，暂时收起列表并锁定资料切换，保存/取消后还原列表尺寸。保存前核对外部修改，冲突时保留草稿，不覆盖其他编辑器的新内容；退出应用有未保存内容时询问保存/放弃/取消。

阅读区保留“编辑笔记”“打开原文件”和“更多操作”。资料信息、打开文件夹、归档及删除收进更多操作；位置、标签和关联信息集中到“资料信息”页签，不再分成多个重复标签页。收集箱支持多选后“归类所选…”，原文件、元数据和已有归档流程保持。

用途、个人记录、标签、关联资料以及项目/Agent 关联在“编辑资料信息”中统一维护；关联资料可直接点击阅读。最近使用只记录实际打开或编辑，不用文件修改时间冒充使用记录。支持标题/标签/用途/个人记录/受限正文搜索；类型、标签和排序在“筛选”中设置，资料多时分页。主题支持重命名、删除空目录及上移/下移，顺序保存在 Vault 的知识库索引中；移动资源会同步更新路径及元数据。

详情区“打开原文件”会通过 Obsidian 打开 Vault 内原件，“更多操作 → 打开文件夹”会打开原件所在目录；Vault 外的外部引用不能在 Obsidian 中打开，可从文件夹查看位置。删除资料会把所选库内文件或独立资料目录移入系统回收站，并移除登记；库外引用不会被删除。没有独立目录的合集须逐项处理。清空回收站时，库外引用仅移除登记、保留源文件；无独立目录的合集仅移除合集登记、保留成员文件。旧知识库回收站仍可用于处理历史记录。归档后原主题目录中的空子目录会清理，空主题可删除。正文与附件保存在 Vault 文件中；SQLite 保存可重建索引、标签、收藏、用途、个人记录、关联、最近使用时间、归档状态、外部引用和资源组合集。首次打开时会将旧资源 JSON sidecar、`.kref` 引用和资源组 JSON 各导入一次；导入记录留在数据库，原文件保留作迁移凭据，导入后不再读取其后续改动。若工作台仍有旧“资源”目录，可在“管理 → 迁入旧工作台资源”中将 Markdown 登记为知识库外部引用，并一次性迁入标签、收藏、项目关联和原有类型等元数据；来源文件及附件留在原目录且不被覆盖或删除。迁入数据库后，后续外部改动不会再次同步。备份数据库会包含这些索引和元数据，换电脑时需同时迁移 Vault 正文与附件。原 Markdown frontmatter 中的标题/标签会被读取，历史原文不批量改写。扫描跳过隐藏目录、凭据、系统规则、日记和项目联接，不递归导入项目源码。最多索引 20,000 文件、12 层目录，每页 200 项；正文读取有总量与单文件上限。原件无法访问时仍保留失效记录。Markdown 编辑会检查外部修改，保留 UTF-8 BOM 和换行格式。

#### 生成的文档怎么命名
应用写进 Vault 的文件统一采用「名称-短编号」，名称在前，8 位短编号保证不重名：

| 位置 | 命名示例 | 说明 |
| --- | --- | --- |
| `selfManger/计划/安排/` | `个人云盘或者syncPan-a5054891.md` | 计划与复盘用标题 |
| `selfManger/资源/` | `FinalShell-499498d9.md` | 工具与资源用名称 |

应用生成的计划与项目资源 Markdown 仍按表格中的规则命名。旧资源 sidecar 和资源组 JSON 只作为一次性迁移来源，不再创建或改写；旧 `.kref` 也只导入一次，之后外部引用身份、资源元数据与合集成员由 SQLite 管理。原文件不会被迁移器删除。

既有项目正文保持在项目工作区，旧关联资源记录保留；通用 Agent 管理页已退场，项目 Agent 文档与 Skills 保留。侧栏入口顺序见本说明开头；工具与环境页提供 SQLite 快捷入口和只读环境检查。

### 整个目录与多文件资源

一条资源可以是独立文件，也可以包含整个 Skill 目录、课程笔记或多份文件/链接。“更多添加”支持整个目录引用；高级文件收集可将多文件组成一条资源，也可分别添加，或加入已有资源。拖入一个目录可直接登记整体资源。原文件不移动，目录内部结构保留。

已有零散资料可 Ctrl 多选后在右键菜单中选择“整理到新文件夹…”，在当前主题下创建实体文件夹并将原件移动进去；若只需归类单项，可选择“整理到专题…”。历史资料合集仍可浏览，移动目录型合集会移动原目录。

搜索会检索内部文件的标题、标签与受限正文，并在资源结果中标明命中的文档，选择结果会预览第一个命中项。主列表按资源计数，内部内容不重复铺开；资料详情单独显示资源内部内容。只有目录首页实际包含 SKILL.md 才标为 Skill；Skill 使用教程是普通笔记。

资源组记录目录/成员、首页、排除项和逻辑主题，保存于 SQLite；旧 JSON 登记只导入一次并保留原文件。外部目录失效时资源登记仍保留。嵌套目录整体登记后，内部包不重复显示为顶层条目。

## 7. 数据安全

“数据库与 Markdown 整体备份”包含数据库（含设置、知识索引与应用自有工作笔记）、个人计划目录及工作区登记项目的 Markdown 和项目登记快照。旧 `work-summary.md` 首次读取时导入数据库并保留原件；之后新增笔记保存在数据库中。项目非 Markdown 附件、知识库文件、系统凭据及系统/依赖目录不包含。备份时暂停 Obsidian、AI 等外部编辑器；程序阻止数据库写入并检查 Markdown 前后内容。归档内有时间、数据库版本、应用版本和文件哈希清单。备份会创建临时明文工作副本，正常完成后清理，异常退出需检查系统临时目录。请单独保管口令，丢失无法解密；整体备份先恢复到新目录或空目录，原数据库隔离为 `manager.sqlite3.recovered`，默认数据库阻止启动。核对提取结果后，点击“准备可用数据目录…”可生成新的数据目录、个人 Markdown 和项目工作区，不会覆盖隔离恢复目录。可选择将知识库根路径映射到本机已有目录，但知识库正文/附件不包含在整体备份中。准备后核对恢复说明与映射报告，再用 `selfManger.exe --data-dir "<目标目录>\data"` 启动。完成实际恢复演练才算演练通过。

数据安全采用左右布局：左侧列出管家数据库、整体数据库与 Markdown 备份，以及已登记的项目、文件夹、脚本和 Obsidian 资料库。资源级归档使用加密 `.amb` 文件，保存到设置的备份位置；版本列表可校验、恢复到新目录或空目录，也可单独删除所选归档而不删除原始资料或其他版本。整体备份包含数据库、个人计划 Markdown、登记项目 Markdown 与登记快照；不包含知识库正文/附件、项目非 Markdown 附件或系统凭据。整体备份先隔离数据库；点击“准备可用数据目录…”可在新目标生成数据副本并重映射已知路径，旧隔离副本保持不变。知识库只能映射到本机已有目录，不随备份复制；映射报告会显示缺失关联。脚本自动备份可在登记时启用；脚本执行时收到 `SELFMANGER_BACKUP_OUTPUT_DIR` 环境变量，应将归档文件写入该临时目录。支持 Python、PowerShell、批处理和 Bash 脚本。不要把口令或访问令牌写入脚本参数。网盘备份通过把统一备份位置设置为本机同步目录实现。

右侧“保护概览”展示最近备份、内容校验、恢复演练、可见版本数，以及资料与备份位置；版本列表与所选资料联动。选择版本并点击“继续恢复检查”后，程序解锁、检查内容并预览恢复目标。项目、文件夹、资料库和脚本备份恢复到新目录或空目录，不直接覆盖原件。整体备份先隔离数据库；提取完成后使用“准备可用数据目录…”执行校验、已知路径重映射并生成新数据目录。没有可用版本或资料正忙时，继续按钮不可用。

状态只覆盖登记范围和本地可读取到的备份；不会备份云端独有内容、应用账号或安装环境。脚本由用户配置并在本机运行；自动备份仅在管家运行时按每日计划执行。旧的目录变更追踪配置和记录仍保留在本机数据库，但当前页面不再显示该功能。
## 8. Obsidian 联动

新建项目默认只接入 `agent`、`笔记`、`文档` 三个目录。Vault 项目入口本身是普通目录，包含项目说明和三个子联接；任务、里程碑与原文直接编辑同一份文件，源码、依赖、数据库、测试和构建产物留在真实项目中。可取消新建窗口的接入勾选，仅保留项目索引。归档时隐藏整组文档入口，恢复时保留入口说明和原子目录范围；旧项目的整项目联接仍兼容。

“任务”标签顶部的“在 Obsidian 中编辑”打开 `agent/TASKS.md` 任务索引；AI 规划与手动任务卡片中的“打开文档”分别打开对应任务原文。支持登记为 `vault_scope: documents` 的文档子目录联接，仅打开登记范围内且指向当前项目的原文件。

项目使用原登记的入口联接或独立 Vault 策略；不复制项目正文。归档项目会从 Obsidian `03-项目`目录中隐藏入口，取消归档后在原路径恢复联接；联接始终指向 `projects/`中的同一份实际资料。

每日与资源默认放在 `工作区/myself/selfManger`。没有项目工作区时使用 `管家数据/工作台`；设置能选择 Obsidian Vault 内另一个文件夹。

若提示没有知识库，先在 Obsidian 把该文件夹的上级作为 Vault 打开。管家不创建或改写 `.obsidian` 配置。未保存的今日计划还没有文件，先保存一次再打开。

改资料位置不会搬迁旧文件；把旧每日 / 资源文件夹人工复制到新位置，确认后再选择。项目规范仍由原工作区决定。

保存不同的知识库根路径时，如果当前根路径已有 SQLite 索引，管家会询问这是原 Vault 搬迁还是切换到另一个 Vault。确认搬迁会在同一数据库事务中迁移索引身份及库内绝对引用；若目标路径已有索引则拒绝合并，路径设置和原索引保持不变。切换到另一个 Vault 会保留各自索引；取消则不保存新路径。

## 9. 工具与环境

工具与环境入口可登记常用本地软件（`.exe`、`.com`、`.lnk`）或 HTTP(S) 网站，支持编辑、删除登记和通过系统默认程序打开。删除只移除 SQLite 中的入口，不会卸载软件或删除目标文件。网址不得包含账号口令、访问令牌或 API 密钥参数；不支持命令行、安装和更新操作。

开发环境检查只读显示本机平台、Python、Git、SSH 和 GPG 的发现结果。登记入口与现有设置一起保存在管家 SQLite 数据库中，并包含在数据库备份里；不会读取其他项目工具资料或自动导入旧 Catalog 内容。

## 10. 设置

设置页分为“通用、资料位置、备份与安全、高级维护”四组，每组使用单一滚动区，适配浅深主题与窄窗口。通用组包含外观和已保存的运行状态；资料位置分别管理计划 Markdown 与知识库 Vault；备份与安全提供备份目录及统一口令；高级维护包含 Git 令牌、自动备份保留数量与配置迁移。

主题切换立即保存，计划文档目录选择后立即生效。Obsidian 路径和备份目录需要点击各自的保存按钮；备份“浏览”只填入路径，未保存时会显示提示，状态概览继续展示已保存的位置。切换分组保留输入。修改目录不会自动搬迁旧资料；保存备份目录和保存保留数量互不影响，任务运行时拒绝修改这两项。

常用设置只有文字资料位置和备份位置。默认通常可以直接使用。

选择文字资料位置时，推荐选择自己的 Obsidian 知识库内的专用文件夹。如果想随 U 盘带走，选择便携程序目录内的资料文件夹。

更改备份目录只影响以后创建的备份，不搬动旧副本。高级区域调整自动备份保留数；只有新备份成功且旧副本可验证时才清理。电脑维护中的配置导入导出只包含登记和程序设置，不包含项目正文、聊天、备份密码或 SSH 私钥。

Git HTTPS 访问令牌用于 GitHub / GitLab 等 HTTPS 仓库认证，保存在系统凭据库；便携模式下保存在加密口令库，需先解锁。SSH 仓库直接使用本机 SSH 密钥或 ssh-agent；移除 HTTPS 令牌不会影响 SSH。统一备份口令也保存在系统凭据库或便携加密口令库。备份路径可以指向本机网盘同步目录，selfManger 只写入本机目录，云端同步由网盘客户端负责。

## 11. U 盘与换电脑

保留 `portable.json` 和整个便携目录，包括 exe、_internal、data、backups，以及你放在其中的文字资料。不要在移动或升级时只复制 exe。

便携目录内的 SQLite 配置路径随目录或盘符变化，`.amb` 备份可在另一目录校验和恢复。目录外的 Obsidian、项目文件、知识库正文/附件和凭据不会自动装进 U 盘；换电脑需另行携带或恢复，并重新选择资料位置。

升级前请先在“数据安全”中创建并校验备份。替换便携程序时保留 `data`、`backups`、`portable.json` 和个人资料；数据库升级范围以对应版本的发布说明为准。旧 Agent 登记、项目文档、备份和知识库原件不会因为替换程序文件而自动删除。

重要文字资料也要保护：可在数据安全登记工作台资料文件夹为项目 / Obsidian 备份；若它在 myself 内，myself 完整备份会包含它。程序配置导出不代替正文备份。

先在新目录解密并校验整体备份；需要用备份中的管家数据继续工作时，在“数据安全”页点击“准备可用数据目录…”，将数据库与个人/项目 Markdown 生成到新目录并重映射已知路径。核对生成的启动说明和映射报告后，以新 `data` 目录启动。知识库正文/附件、项目非 Markdown 附件和系统凭据不包含在整体备份中，需另行恢复或重新配置。

## 12. 长期行动、项目笔记与内置数据库备份

长期计划详情提供“拆成每日行动”，创建时自动关联当前计划和项目，可选择执行日期。短期任务的“所属长期计划”可选择新旧长期计划，双方使用同一任务记录；计划详情显示关联行动和完成数，双击行动可调整日期或状态。完成行动会计入完成数，整体计划是否达成仍由用户确认。

项目的“笔记”标签提供“新建笔记”“在管家中编辑”和原 Obsidian 入口，无需配置 Obsidian 即可在管家中编写。笔记正文保存在项目的“笔记/”目录；预览保留单行换行。保存前核对原文，外部编辑冲突时保留草稿并拒绝覆盖；归档项目仅阅读。

数据安全的“我的资料”列表自带“管家自身数据库 · 内置”和“数据库与 Markdown 整体备份”两个不可移除的项目。前者以 SQLite 一致性快照生成加密 `.amb`，只包含设置、登记、统一任务、知识索引和操作记录；不包含个人计划 Markdown、项目笔记、附件原件或系统凭据。若要同时备份个人计划目录与登记项目 Markdown，请使用“数据库与 Markdown 整体备份”；项目非 Markdown 附件、知识库正文/附件和系统凭据仍不在其范围内，需要另行保护。数据库归档恢复先解密到新空目录，退出管家并保留当前数据库副本，再按恢复说明放入目标数据目录；不要覆盖正在使用的数据库。

## 13. 常见问题

**项目列表为空：**点项目标题栏右侧“⋯”→“切换工作区…”选择包含 agent/projects.json 的工作区根目录；这不会删除或重建项目。进行中 / 已归档视图和搜索条件也会影响列表。源码运行时，数据目录优先级为命令行 `--data-dir`、环境变量 `SELFMANGER_DATA_DIR`、软件目录中的本机配置 `local-config.json`、便携目录和平台默认目录。启用 `require_existing_database` 后，指定位置缺少数据库会停止启动，不会创建空库。设置页可核对当前数据位置。

**资料看起来消失：**点知识库筛选栏的“×”清除搜索、类型和项目 / Agent 筛选，或从“全部文件”重新浏览。搜索覆盖全部已索引资料，当前列表每页最多显示 200 项；新建资料会继承当前项目 / Agent 关联。

**项目文档不完整：**详情显示缺失或不可读的文档，其他资料仍能查看。打开项目文件夹检查；管家不会用模板覆盖个人原文。


**能提前安排日程吗？** 可以。新建行动或日程时选择日期，也可以在“计划与待办”中切换日期查看跨日安排。行动、日程和重复规则保存在 SQLite；本版不连接外部日历服务，也不会发送日程通知。

**项目总结由哪里维护？** 阶段总结直接写入已有 HANDOFF，避免进度、总结、交接多份正文互相冲突。

**为什么保存提示文件已改变？** Obsidian 或其他程序修改了原文件。关闭弹窗，刷新后重新编辑；管家不会覆盖外部新内容。

**为什么资源没有出现在项目里？** 检查资源条目的“适用项目”是否包含当前项目编号；项目筛选可清除。

**为什么资源状态是“已测试”但实际上不能用？** 状态是人工登记，不是自动连接或检测结果。

**为什么“最近工作”为空？** 它记录从今日进入项目的使用时间，不读取 Agent 私密对话来推断。

**为什么 U 盘换电脑找不到知识库？** 原目录在 U 盘外，需要携带 / 恢复并重新选择。选择资料位置不会自动移动旧文件。

**恢复会覆盖正在用的文件吗？** `.amb` 只恢复到新目录或空目录；整体备份先隔离数据库，再由“准备可用数据目录…”生成新启用目录，不会改写隔离副本。核对启动说明与映射报告后，使用新 `data` 目录启动。恢复范围和限制见“换电脑恢复说明”。

**启动 DLL 错误怎么办？** 用对应系统的完整新运行包解压，不混用历史 _internal 文件；源码需虚拟环境与完整 Qt 依赖。仍失败时检查数据安全里的诊断或运行包启动诊断。
